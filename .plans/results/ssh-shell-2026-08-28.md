# Results: Interactive SSH Shell Alongside SFTP (plan `plan-ssh-shell.md`)

**Date:** 2026-08-28
**Status:** Complete — all plan steps implemented and verified.

## What was built

### `surftp/shell/` — the emulator split

- **`protocol.py`**: The parent↔child wire format, framed with msgpack (not
  pickle) and a 4-byte length prefix. One place holds the schema: `feed` /
  `resize` / `quit` parent→child, `frame` / `ack` child→parent. Frames carry
  **runs** (`[text, fg, bg, flags]`) rather than cells so a 120×40 screen fits
  in the low kilobytes.
- **`emulator.py`**: The child-process entry point. Runs `pyte` + frame
  coalescing (at most one frame per 33 ms), imports neither `asyncssh` nor
  `textual`, and writes nothing but frames and acks back. It cannot
  authenticate anything — it gets terminal bytes only.
- **`session.py`**: `ShellSession` — the parent side. Opens the shell channel
  on the **existing** authenticated `SSHSession` (a second channel next to
  SFTP, never a second connection), spawns the emulator with the `spawn`
  context, and implements the back-pressure window: above `MAX_UNACKED`
  (256 KB) it stops reading the SSH channel entirely, so a flooding command
  costs ~6% of concurrent SFTP throughput instead of ~57%. The child pipe is
  read on a worker thread (`next_message`), never the event loop.

### `surftp/widgets/` — the UI

- **`terminal.py`**: `TerminalView` — paints the latest frame as styled runs
  with a reverse-video cursor, and translates Textual key events into the
  bytes a shell expects (arrows/home/end/page → xterm sequences, ctrl+letter →
  control byte). One key map lives here.
- **`bottom.py`**: `BottomPanel` — a `TabbedContent` whose first tab is the
  (unchanged) `TransferPanel` and whose remaining tabs are one per shell.
  Shell tabs are added/removed as shells open and close.

### App integration

- **Bindings**: `ctrl+enter` opens a shell on the active session tab, `f10`
  always returns focus to the panes (the escape hatch from a shell).
- **`App.check_action()`**: disables pane/transfer actions while a
  `TerminalView` has focus, so `tab`, `ctrl+d`, `escape`, `ctrl+w`,
  `ctrl+pageup/pagedown` reach the shell instead of the app. `f10` and
  `ctrl+q` stay available.
- **Lifecycle**: closing a session tab kills its shell's child process
  (`close_shell`); `close_everything` walks all shells then all connections.

## Deviations / discoveries

1. **The drain read size was the first real bug.** `asyncssh`'s
   `SSHReader.read(n)` waits until *n* bytes are available, so a 64 KB chunk
   stalled the drain behind a trickle of shell output. Reduced `READ_CHUNK` to
   4096.

2. **The emulator's coalescing deadlock.** If a feed arrived inside the 33 ms
   window, the child marked the screen dirty but then blocked on `recv_bytes`
   and never emitted the pending frame — a stalled-looking terminal. Fixed by
   polling the pipe with a timeout and flushing any due frame on timeout.

3. **`change_terminal_size` breaks the asyncssh test server.** The client-side
   call sends a window-change request; the server's `process_factory` bridge
   must handle `TerminalSizeChanged` by continuing (the subprocess has no PTY
   to resize). Real OpenSSH handles this natively; the test server's bridge now
   swallows it and keeps copying.

4. **`BottomPanel` must not override `compose()`.** The base
   `TabbedContent.compose()` is what builds the internal `ContentTabs` widget
   that `add_pane`/`remove_pane` rely on. My first version overrode `compose()`
   to declare the Transfers tab directly, which left `ContentTabs` missing and
   made `add_pane`/`remove_pane`/`_on_tab_pane_focused` raise `NoMatches`.
   Every tab — including Transfers — is now added via `add_pane` in
   `on_mount`.

5. **`_on_tab_pane_focused` must be silenced in BottomPanel.** The base handler
   reacts to focus from *any* descendant TabPane; with session tabs in sibling
   `TabbedContent` widgets, their panes' focus events would otherwise make the
   bottom panel try to activate a tab it does not own. It now stops the event
   and activates nothing — shell tabs are activated explicitly.

6. **`test_sessions.py` requires the event loop to stay free while reading the
   child pipe.** Calling `next_message()` (blocking) on the loop froze the
   drain task; the integration test reads via `asyncio.to_thread`, exactly the
   plan's "read the pipe on a worker thread" rule.

## Verification performed

### Unit (no network) — `tests/test_shell.py` (17 checks)
- Protocol: encode/decode, framing, multi-message chunks, partial-frame
  buffering.
- Emulator (real spawned process): plain text, ANSI colour runs, resize
  mid-stream, coalescing cap, QUIT stops the child, parent EOF stops the child.
- Key translation: printable, enter/backspace, arrows, home/end/page, ctrl
  letters, f-keys, unknown keys → empty.

### Integration (real asyncssh server) — `tests/test_shell_integration.py`
- Echo over the shell produces a frame containing the output.
- SFTP still lists while a shell channel is open (concurrent channels).
- Closing a shell terminates its child process.

### Existing suites — all pass unmodified (plan §9)
- `test_ui.py`, `test_ui_connect.py`, `test_sessions.py`, `test_vault.py`,
  `test_integration.py`, `test_ftp.py`, `test_permissions.py`,
  `test_session_tabs.py` — all green.

### UI wiring (pilot)
- Bottom panel hosts the transfers panel; `ctrl+t` still toggles it.
- Opening a shell on a local pane is refused with a notification (no crash).
- `f10` focuses panes; app actions are disabled only while a terminal is
  focused.

## Out of scope (per plan)

Mouse reporting, `sudo` prompt detection, shell-over-FTP, splitting one shell
across both sides, and persisting shell history — none implemented, as
specified.

## What this sets up

The tunnel plan (`plan-tunnel.md`) can now rely on the same "one connection,
many channels" property the shell exercises: SFTP and a shell already coexist
on one authenticated `SSHSession`. The shell's back-pressure window is also the
template the tunnel will need for not letting a flood starve the UI.
